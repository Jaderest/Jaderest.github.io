为什么需要并行计算

提高计算性能

提高计算性能的主要手段

  • 提高处理器字长
  • 提高集成度
    • 摩尔定律
  • 流水线等微体系结构技术
    • RISC
    • 5级流水线
    • 分支预测、寄存器重命名、超长指令字、超标量、乱序执行、cache等
  • 提高处理器频率

单核处理器性能提升接近极限

  1. 超大规模集成电路的集成度不可能无限制提高
  2. 处理器的指令级并行度提升接近极限
  3. 处理器速度和存储器速度差异越来越大
  4. 功耗和散热大幅增加超过芯片承受能力

单处理器向多核/众核并行计算发展

  1. 多核处理器
  2. 众核处理器
  3. 众核GPU

应用领域计算规模核复杂度大幅提高

  • 爆炸性增长的的Web规模数据流
  • 超大的计算量/计算复杂度

并行计算技术的发展趋势和影响

  • 越来越多的研究和应用领域将需要使用并行计算技术
  • 并行计算技术将对传统计算技术产生革命性的影响

为什么需要学习并行计算技术

  • 软件开发/程序设计人员面临挑战
    • 过去20-30年里程序设计技术的最大革命是面向对象技术
    • 下一个程序设计技术的革命将是并行计算技术
    • 今天绝大多数程序员不懂并行设计技术

并行计算技术的分类

按数据和指令处理结构：弗林(Flynn)分类法

  • SISD
  • SIMD
  • MISD
  • MIMD
  • single instruction, single data

按并行类型分类

  • 位级并行
  • 指令级并行
  • 线程级并行
    • 数据级并行：一个大的数据块划分为小块，分别由不同的处理器/线程处理
    • 任务级并行：一个大的计算任务划分为子任务分别由不同的处理器/线程处理
    • 注意也有结合以上两种并行方式的情况

按存储访问结构分类

  1. 共享内存
  • 所有处理器通过总线共享内存
  • 多核处理器，SMP……
  • 也称为UMA（Uniform Memory Access）
  1. 分布式共享存储体系结构
  • 各个处理器有本地存储器
  • 同时再共享一个全局的存储器
  1. 分布式内存(Distributed Memory)
  • 各个处理器使用本地独立的存储器
  • 2和3也称为NUMA(Non-Uniform Memory Access)

按系统类型分类

需要考虑的属性

  • 耦合度：由紧密到松散
  • 可扩展性：由低扩展性到高扩展性
  • 能耗：由低能耗到高能耗

分类

  • 多核/众核并行计算系统MC（Multicore）/CMP（Chip-level multiprocessing）
  • 对称多处理系统SMP（Symmetric Multiprocessing）
    • 多个相同类型处理器通过总线连接并共享存储器
  • 大规模并行处理MPP（Massively Parallel Processing）
    • 专用内联网连接一组处理器形成的一个计算系统
  • 集群（Cluster）
    • 网络连接的一组普通商用计算机构成的计算系统
  • 网格（Grid）
    • 用网络连接远距离分布的一组异构计算机构成的计算系统

不同系统的特征和对比

从MC到Grid，耦合度越来越低，但可扩展性越来越高，系统规模越来越大，而能耗也越来越高

  • MC处理器核通过NOC(片上网络)集成在一个芯片上，通常使用混合式内存访问机制(本地缓存加全局内存)，功耗很低
  • SMP使用独立的处理器和共享内存，以总线结构互联，运行一个操作系统,定制成本高,难以扩充,规模较小（2-8处理器）
  • MPP使用独立的处理器及独立的内存、OS，专用的高速内联网络，难以升级和扩充，规模中等(TOP500中有80多个，天河那些超算)
  • Cluster使用商品化的刀片或机架服务器，以网络互联为一个物理上紧密的计算系统，可扩展性强，规模可小可大，是目前高性能并行计算最常用的形式（TOP500中有400多个）
  • Grid则为地理上广泛分布的异构计算资源构成的一个极为松散的计算系统，主要用于并行度很低的大规模科学计算任务

按计算特征分类

  • 数据密集型并行计算
  • 计算密集型并行计算
  • 数据密集与计算密集混合型并行计算

按并行程序设计模型/方法分类

  • 共享内存变量
    • Pthread, OpenMP：共享内存式多处理并行编程接口
  • 消息传递方式
    • MPI：Message Passing Interface 消息传递并行编程接口标准
  • MapReduce

不同类型并行计算技术和系统的发展历史和现状

  • 主要发展历史阶段
    • 1975-1985：向量机技术（同时能够处理多个数据）
    • 1986-1995：大规模并行处理MPP，MPI得到开发应用
    • 1995-现在：Cluster和Grid并行计算技术成为主流
  • 主要发展趋势
    • SMP作为共享内存式小规模并行计算技术一直活跃
    • 多核/众核并行计算成为重要发展趋势
      • 单核处理器性能瓶颈 + 多核/众核计算体积小、功耗低等优点，它成为必然趋势
    • 并行计算软件技术远远落后于硬件发展速度
      • 缺少有效的并行计算软件框架、编程模型和方法

并行计算的主要技术问题

  • 多核/多处理器网络互联结构技术
  • 存储访问体系结构
  • 分布式数据与文件管理
  • 并行计算任务分解与算法设计
  • 并行程序设计模型和方法
  • 数据同步访问和通信控制
  • 可靠性设计与容错技术
  • 并行计算软件框架平台
  • 系统性能评价和程序并行度评估

多核/多处理器网络互联结构技术

主要研究处理器间互联拓扑结构，尤其在包含大量处理器的并行计算系统中，需要具有良好的互联结构，以保证大量处理器能真正有效地协同工作，获得应有的并行计算效率。

  • 共享总线连接（Shared Bus）
  • 交叉开关网络（Crossbar Switch）
  • 环形结构（Torus）
  • Mesh网络结构（Mesh Network）
  • 片上网络（NOC，Network on Chip）
  • etc.

存储访问体系结构

主要研究不同的存储结构，以及在不同存储结构下的特定技术问题

  • 共享存储器体系结构（Shared Memory）
    • 共享数据访问和同步控制
  • 分布存储体系结构（Distributed Memory）
    • 数据通信控制和节点计算同步控制
  • 分布共享存储结构（Distributed Shared Memory）
    • Cache的一致性问题
    • 数据访问/通信的时间延迟

有分布就必然会要考虑通信与同步

分布式数据与文件管理

在大规模集群环境下，如何解决大数据块的存储和访问管理；尤其是数据密集型并行计算时，理想的情况是提供分布式数据与文件管理系统，例如

  • Google的GFS（Google File System）
  • Hadoop的HDFS（Hadoop Distributed File System）
  • etc.

并行计算任务分解与算法设计

含义：一个大型计算任务如何从数据上或者是计算方法上进行适当的划分，分解为一组子任务以便分配给各个节点进行并行处理，如何搜集各节点计算的局部结果

  • 数据划分：如何将特大的数据进行划分并分配给各节点进行处理
  • 算法分解与设计：一个大的尤其是计算密集型的计算任务，首先需要寻找并确定其可并行计算的部分，然后进一步寻找好的分解算法：可把一个整体的算法 纵向分解为一组并行的子任务，或者对于复杂的计算任务可横向分解为多个并行处理过程。

并行程序设计模型和方法

根据不同的硬件构架，不同的并行计算系统可能需要不同的并行程序设计模型和方法，例如

  • 并行程序设计模型和方法
    • 共享内存式并行程序设计：为共享内存结构并行计算系统提供的程序设计方法，需提供数据访问同步控制机制（如互斥信号，锁等）
    • 消息传递式并行程序设计：为分布内存结构并行计算系统提供的、以消息传递方式完成节点间数据通信的程序设计方法
    • MapReduce式并行程序设计：综合编程框架，提供一种简便易用的并行程序设计方法
  • 并行程序设计语言
    • 语言级扩充，使用宏指令在普通的程序设计语言上增加一些并行计算宏指令
    • 并行计算库函数与编程接口：如MPI，CUDA（NVIDIA GPU）
  • 并行编译与优化技术
    • 编译程序需要考虑编译时的自动化并行性处理，以及为提高计算性能进行并行计算优化处理
